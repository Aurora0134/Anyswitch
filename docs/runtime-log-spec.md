# 运行日志级别现行规格

> 本文件是 Anyswitch 运行日志事件分级的单一现行规格，适用于进入面板「运行日志」区的条目。改动分级规则时，同笔更新本文件。日志总线契约见 [贡献指南的日志条目](../CONTRIBUTING.md#规格同笔更新约定)。

## 1. 按操作结果分级

| 级别 | 判定 | 例子 |
|---|---|---|
| `ERROR` | Anyswitch 承担的结果已确认未达成，自身服务确认无法履行职责，或数据完整性无法保证。 | 保存关键状态失败、终端宿主关停时仍有待处理任务、本地凭据无法读取或解密、本轮适用端点全部同步失败。 |
| `WARN` | 值得关注的上游或请求终态失败、部分成功，或用户可感知的能力降级。 | 上游流最终失败、渠道进入熔断或退避、回退到纯文本请求时舍弃图片、可选自动下载未启动但已安装版本仍可用、已启用的看门狗迁移未获确认。 |
| `INFO` | 已验证的里程碑、有记录价值的常规事实或按配置执行的兼容行为。 | 服务探测确认就绪、配置确实写入、按用户配置启用兼容路径。 |
| 不记录 | 预期的轮询、取消、常规校验拒绝、无变化或对用户透明的中间尝试。已有状态或指标足以说明结果时，沿用原有观测。 | 状态轮询结果未变、用户取消请求、输入未通过常规校验、无损重试中的单次尝试失败。 |

级别按当前操作承担的结果和已知影响判定。启动调用成功或取得 PID 只证明进程已拉起，就绪须另有可用性证据。保留旧状态或回滚成功只说明原状态得到保护，原操作仍按未达成的结果记录。HTTP 状态码、异常和 `stderr` 可供诊断，单凭其中任何一项都无法确定级别。

### 流式请求

相同结果在各协议和入口使用同一级别。现有七处流式终态告警均保留 `WARN`，包括保活结束时最终收到上游失败状态，以及 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 各自的内容交付后失败和交付前尝试耗尽。流式行为、指标和面板过滤规则沿用现有契约。实现见 [流转发模块](../src/relay/stream-pipe.mjs)。

## 2. 事件归属与跨进程转发

- 由掌握事件结果的源头定级。转发已有级别的条目时保留原级别。同一事件只记录一次；确有不同含义的状态变化与诊断细节可以分别记录。日志不得包含凭据，沿用现有日志通道。
- 端点配置同步的旧子进程通过非结构化 `stdout` / `stderr` 传送诊断。父进程依据进程状态和结构化同步结果对整轮定级，流的选择只用于传输诊断。每轮至多一条结果汇总，单端点诊断可另留。确认写入的配置更新可按 `INFO` 记录一次。同步 API 和退出码沿用现有契约。见 [同步子进程](../src/agents/agent-sync-run.mjs) 与 [同步拉起端](../src/agents/agent-sync-spawn.mjs)。

| 整轮同步结果 | 父进程的失败汇总 |
|---|---|
| 进程失败、整轮结果报告失败，或 `failed` 非空且 `synced` 为空 | `ERROR` |
| 同步部分成功，`failed` 和 `synced` 均非空 | `WARN` |

本轮各端点均因未安装而跳过或配置无变化时，父进程不输出整轮结果汇总。未安装端点的逐端点 `INFO` 诊断照常保留。

## 3. 评审要求

新增或改动日志时，核对各分支的实际结果及用户可见影响，确认去重后仍能区分状态变化与诊断。沿实际转发路径核对面板收到的级别，源头的调用级别只作为起点。对有意义的分支和结果补充或更新测试，覆盖应记录的级别及应保持静默的情形。
